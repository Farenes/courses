# ПРИМЕРЫ тем
1. Система записи к специалистам
Клиент, специалист и администратор. Слоты, заявки со статусами (создана → подтверждена → завершена / отменена), напоминания. Хорошо закрывает state-диаграммы, роли, нагрузку на запись и контроль доступа.

2. Внутренний helpdesk / трекер заявок
Пользователь создаёт тикет, исполнитель берёт в работу, есть приоритеты и SLA. Классическая предметная область для аналитики и архитектуры: очереди, статусы, роли, уведомления.

3. Бронирование аудиторий / оборудования
Календарь, конфликты слотов, согласование, отмена. Бизнес-правила (нельзя дважды занять одно время) легко тестировать unit-тестами; e2e — полный путь «заявка → подтверждение».

4. Обмен книгами / вещами в общежитии
Объявления, бронирование, статусы сделки, жалобы. Несколько ролей, модерация, поиск — достаточно объёма без перегруза.

5. Квизы и живые сессии
Преподаватель собирает квиз, запускает сессию, студенты отвечают, считается рейтинг. Есть сущности с жизненным циклом (квиз, сессия, попытка) и понятный realtime/polling-контур.

6. Учёт личных финансов (web)
Счета, категории, транзакции, бюджеты, отчёты. Богатая доменная модель и валидация; деплой и бэкапы БД выглядят естественно.

7. Peer-review домашних работ
Студент сдаёт работу, ревьюер комментирует, преподаватель принимает. Статусы работы, права доступа к чужим файлам — сильный материал для сценариев и тестов безопасности.

8. Пошаговая онлайн-игра с комнатами (не «графический шедевр»)
Лобби, матч, ходы, рейтинг, история партий.

9. Telegram-бот предметной области + админ-панель
Например: запись на консультации, учёт дежурств группы, заявки в общежитие, трекер привычек с напоминаниями. Telegram — внешняя система на C4 Context; своя логика, БД и web-админка — отдельные контейнеры. Не «обёртка над ChatGPT».
